  - **Mechanical fix (compose.py, applied directly, no proposal needed):** the CTA button's arrow "→" intermittently rendered as a missing-glyph tofu box — happened on this run's Kazakh slides. Root cause: `Face.__init__` created a brand-new `ImageFont.truetype` object on every call with no caching, so once an earlier font object was garbage-collected, Python could reuse its `id()` for an unrelated later font object; `Face._has()`'s glyph-presence cache is keyed by `id(font)`, so a stale cache entry from a dead, unrelated font object could wrongly report "no arrow glyph" for a live one. Fixed by caching loaded font objects by `(path, size, weight)` at the class level so they're never GC'd mid-run and `id()` stays stable. Verified by re-rendering all 12 images after the fix — arrow renders correctly on every RU/KK/EN slide. Worth watching for: this class of bug (id() reuse corrupting an id-keyed cache) could in principle affect other glyphs too, not just →; no other symptom seen so far.
